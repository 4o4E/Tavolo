# 下游文本字体回退：emoji 与 grapheme cluster

本文档面向 Tavolo 下游使用方，说明 Compose `text(...)` 的字体回退机制。`2.5.0` 起支持 Skia Paragraph 的常规 emoji fallback（字体兜底）；`2.7.1` 起补充 grapheme cluster（用户感知字符簇）级别的同字体成形兜底，用于处理组合包围符号等不能被拆开的 Unicode 序列。

## 变更概览

从 `2.5.0` 开始，`graphics` 模块中的 Compose `text(...)` 默认走 Skia Paragraph 渲染。
这意味着：

- 主字体仍然只需要传一个 `fontFamily`
- 只要主字体和 emoji 字体都注册到 `FontManager`，缺字时会自动回退
- 不需要在业务侧手动拆文本，也不需要单独检测 emoji

从 `2.7.1` 开始，`text(...)` 内部会使用 ICU4J 按 extended grapheme cluster 规则切分文本。组合符号、emoji ZWJ、regional indicator（区域指示符，常用于国旗 emoji）、variation selector（变体选择符）和 emoji modifier（肤色等修饰符）不会在测量、ellipsis 或 `AnnotatedText` span 合并时被拆开。换行优先使用 ICU line break（换行断点）规则；只有一个断点段本身放不下时，才按 grapheme cluster 继续拆分。

## 机制分层

### 1. 常规缺字仍交给 Skia Paragraph

普通中文、英文、常见 emoji 和复杂脚本文字默认仍走 Skia Paragraph 的字体 fallback。Tavolo 不会把整段文本强制切到符号字体，也不会改变业务层 `fontFamily` 只传一个主字体名的语义。

### 2. 风险 cluster 才进入 Tavolo 兜底

当某个 grapheme cluster 含有 combining mark（组合符号）、enclosing mark（组合包围符号）、ZWJ、regional indicator、variation selector 或 emoji modifier 时，Tavolo 会检查主字体是否能用同一个 `Typeface` 覆盖并正确成形这个 cluster。

例如 `୧⍤⃝` 中的 `⍤⃝` 如果被拆成不同字体 run，组合圈 `⃝` 就可能无法贴到 `⍤` 上。此时 Tavolo 会为整个 cluster 选择一个可用字体，并改用 Skia `TextLine` 做同字体 shaping（文本成形）后绘制。

### 3. 字体候选顺序

风险 cluster 的候选字体来自：

1. 当前 `fontFamily`
2. `FontManager.graphemeClusterFallbackFamilies`
3. 已注册到 `FontManager` 的字体名
4. `FontManager.defaultFamily`
5. 少量常见 enclosing mark 兜底字体名，如 `FreeMono`、`GNU Unifont`
6. Skia 系统字体匹配结果

对 enclosing mark，Tavolo 不只检查 glyph（字形）是否存在，还会用 `TextLine` 的 glyph 位置和 bounds 验证组合圈与基字是否有有效重叠。这样可以过滤“字体有这个码点，但实际画出来仍然漂移”的情况。

### 4. 触发范围

只有当前文本中确实存在需要强制同字体成形的风险 cluster 时，Tavolo 才会绕过 Paragraph 的整段布局，改用内部布局与绘制。内部布局仍优先按 ICU line break 断行，grapheme cluster 只是最小不可拆单元，不会把普通英文段落直接降级成逐字符换行。普通文本仍保持原 Paragraph 路径。

如果某个非 enclosing 风险 cluster（如 `❤️`、`👨‍👩‍👧‍👦`、`👍🏽`、`🇨🇳`）找不到可证明能正确成形的单一字体，Tavolo 会把这个 cluster 单独交回 Skia Paragraph 绘制，让 Paragraph 继续使用字体集合 fallback，而不是用主字体逐码点 `drawString`。

## 下游需要做什么

升级依赖到包含所需能力的版本，例如 `2.7.1`：

```kotlin
val version = "2.7.1"

dependencies {
    implementation("top.e404.tavolo:tavolo-core:${version}")
    implementation("top.e404.tavolo:tavolo-graphics:${version}")
    implementation("top.e404.tavolo:tavolo-gif-codec:${version}")
    implementation("top.e404.tavolo:tavolo-common:${version}")
}
```

然后在渲染前注册：

1. 主文本字体
2. 一套 emoji 字体

业务代码仍然只把主字体传给 `text(...)`。

## 推荐接入方式

### 方案一：使用系统字体

适合桌面程序、Windows 服务、已经明确安装系统字体的机器。

```kotlin
import top.e404.tavolo.util.FontManager

val uiFont = FontManager.registerSystem("ui", "Microsoft YaHei")
FontManager.registerSystem("emoji", "Segoe UI Emoji")
FontManager.defaultFamily = uiFont
```

渲染时仍然只使用主字体：

```kotlin
render {
    text(
        "你好 😀 😂 ❤️",
        fontSize = 28f,
        fontFamily = uiFont
    )
}
```

### 方案二：随包分发字体文件

适合 Linux 服务端、Docker 容器、精简运行环境。

```kotlin
import java.io.File
import top.e404.tavolo.util.FontManager

val uiFont = FontManager.registerFile("ui", File("font/NotoSansCJKsc-Regular.otf"))
FontManager.registerFile("emoji", File("font/NotoColorEmoji.ttf"))
FontManager.defaultFamily = uiFont
```

这种方式更稳定，不依赖目标机器是否预装字体。

### 方案三：为特殊 grapheme cluster 配置兜底字体

如果业务文本包含 `A⃝`、`1⃝`、`୧⍤⃝` 这类组合包围符号，建议额外准备一个能正确绘制 enclosing mark 的字体，并放入 `graphemeClusterFallbackFamilies`。

```kotlin
import java.io.File
import top.e404.tavolo.util.FontManager

val uiFont = FontManager.registerFile("ui", File("font/NotoSansCJKsc-Regular.otf"))
val clusterFont = FontManager.registerFile("cluster-symbol", File("font/FreeMono.ttf"))

FontManager.defaultFamily = uiFont
FontManager.graphemeClusterFallbackFamilies = listOf(clusterFont)
```

`FreeMono.ttf` 对 `⍤⃝`、`A⃝`、`1⃝` 这类组合圈效果较好。若部署环境无法使用 FreeMono，可以测试 GNU Unifont；它覆盖面大，但视觉风格更接近兜底字体，不适合追求精细排版的正文。

## 平台建议

- Windows：优先使用 `Segoe UI Emoji`
- Linux：优先使用 `Noto Color Emoji`
- 容器环境：建议把主字体和 emoji 字体一起随应用分发
- 组合包围符号：优先把 FreeMono 这类已验证字体放到 `FontManager.graphemeClusterFallbackFamilies`

## 兼容性说明

当前的字体回退主要覆盖 Compose `text(...)` 路径。
如果下游仍然直接使用 Skia `TextLine.make(...)` 或 `Canvas.drawTextLine(...)`，不会自动获得这套多字体回退能力。

也就是说：

- `text(...)`：支持自动 fallback 和 grapheme cluster 边界保护
- `TextLine.make(...)`：仍然是旧路径，需要下游自己迁移或自行处理

## 当前限制

### 1. 公开 API 仍然是单主字体

当前 `fontFamily` 仍然只接受一个名字，不支持显式传入多字体优先级列表。  
emoji 回退依赖 `FontManager` 中已注册的字体集合自动完成。特殊 grapheme cluster 可以通过 `FontManager.graphemeClusterFallbackFamilies` 指定更靠前的兜底候选。

### 2. 组合 emoji 是否完全显示，取决于字体本身

例如家庭、职业、性别这类 ZWJ 组合 emoji，是否能合成为单个图形，不完全由 Tavolo 决定，还取决于目标平台上的 emoji 字体能力。Tavolo 会保证它们作为同一个 grapheme cluster 参与测量和截断，但最终显示样式仍由字体决定。

常见单字符 emoji 如：

- `😀`
- `😂`
- `🥰`
- `❤️`

通常问题不大。

## 推荐自检

升级后建议下游至少人工验证一张包含以下内容的图片：

- 中文
- 英文
- 常见 emoji
- emoji ZWJ 组合
- 国旗 emoji
- `A⃝`、`1⃝`、`୧⍤⃝`
- 混排换行
- 带 `letterSpacing` 的文本

示例文本：

```text
中文 English 😀 😂 🥰 ❤️
中文、English 和 emoji 混排换行：😀a
cluster: ୧⍤⃝ A⃝ 1⃝ 🇨🇳 👨‍👩‍👧‍👦 é
```

重点观察：

- 是否出现方块字或空白
- emoji 和国旗是否被拆成无效字符
- 组合圈是否贴在基字上
- 换行是否优先在单词或 ICU line break 断点处发生
- 省略号是否切在完整 cluster 后

项目内置了一组人工测试，准备 `run/font/FreeMono.ttf` 后运行：

```shell
./gradlew :graphics:manualTest --tests "*ComposeTextFallbackManualTest"
```

输出位于 `run/out/compose`：

- `文本-fallback-01-grapheme-cluster-综合.png`
- `文本-fallback-02-换行省略和行内样式.png`
- `文本-fallback-03-字体候选和混排边界.png`

## 迁移结论

下游升级后，最稳妥的做法是：

1. 统一使用 Compose `text(...)`
2. 启动时注册主字体和 emoji 字体
3. 需要组合包围符号时，把已验证字体加入 `FontManager.graphemeClusterFallbackFamilies`
4. 业务层继续只传主字体名

这样就能在不改业务文本生成逻辑的前提下，获得常规缺字回退和风险 grapheme cluster 的同字体成形保护。
